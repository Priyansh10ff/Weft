The problem

Text-only RAG reads the transcript and misses the rest.

In a recorded design review, the speaker says “this is how we cut database load” while the diagram that explains it is on screen. Chunk the transcript and embed it, and the diagram, the numbers on the slide and the speaker are gone.

BEFORETranscript chunks

  • Fixed-size chunks that cut sentences and slides in half
  • Diagrams, charts and on-screen text never indexed
  • No idea who said what, or when
  • A PDF page and the video that discusses it stay unrelated
  • Answers you cannot check against the source

WEFTWoven evidence

  • Segments follow scene changes and sentence boundaries
  • Every frame, page and image described, with OCR located by bounding box
  • Speech attributed to speakers, every segment timestamped
  • Shared entities link a spoken explanation to the slide and the doc
  • Each answer cites the exact second, page or region it used

How it works

Ingest. Weave. Retrieve.

Existing models do the perception. Weft does the data management: what each piece of evidence is, where it came from, and how it connects to everything else.

01 / INGEST

Extract with provenance

Each modality goes through the right extractor, and every output keeps its source, location and confidence.

  • Whisper speech with per-sentence timestamps
  • Scene detection and keyframes for video
  • Vision summaries, OCR blocks and regions
  • Exact PDF text layer, OCR for scans
02 / WEAVE

Link across modalities

Segments become nodes in a graph, connected by typed, confidence-weighted relations.

  • Typed entities shared across files
  • Speakers resolved from the recording itself
  • Temporal order within every source
  • SQLite system of record, rebuildable index
03 / RETRIEVE

Answer with evidence

Search runs over speech, text and visual descriptions together, and the answer cites what it used.

  • Retrieval across all modalities at once
  • Grounded answers with inline citations
  • Jump to the second, page or region
  • Side-by-side text-only baseline

Traceability

Answers you can check.

Inline citations

Every claim points to the evidence card it came from, colour-coded by modality.

Jump to the moment

Video and audio open at the cited second; PDF pages and images open with the matching regions outlined.

Confidence you can see

Each segment carries its extractor's confidence, so a shaky transcription or failed vision call is visible, not hidden.

API

Built to sit under your RAG stack.

Everything in the workspace is a documented HTTP endpoint. Upload sources, poll jobs, query, and inspect the graph directly.

# upload a recording as a background job
curl -F "file=@design-review.mp4" \
  "localhost:8000/upload/video?background=true"

# poll it
curl localhost:8000/jobs/{job_id}

# ask across everything
curl -X POST localhost:8000/query \
  -H "Content-Type: application/json" \
  -d '{"query": "who explained the cache design?"}'
// every result is a segment with full provenance
{
  "segment_id": "5b0c…",
  "modality": "video",
  "source": "design-review.mp4",
  "timestamp": "12:40 - 13:05",
  "transcript": "…we put Redis in front of the read replicas…",
  "visual_summary": "Diagram: API → Redis → 2 replicas",
  "frame_path": "/derived/…/scene_004_12_58.jpg",
  "confidence": 0.83,
  "entities": ["Redis", "read replicas"]
}
